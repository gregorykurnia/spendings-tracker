# Changelog

One to three lines per entry; details are in the commit body.

## 2026-10-25
- Redesign 1.1: safe test setup. Vitest (`npm test`), emulator tests (`npm run test:db`), Playwright on a `.next-test` build against the Firestore emulator (`npm run test:e2e`), `npm run seed:emulator` (normal and stress sets), smoke spec. `firebase.ts` refuses the emulator unless the project is a `demo-` one.
- Redesign 1.2: data layer. Waiting lines gain direction, bank line, order, kept, suggestion and own-transfer fields; hooks for screenshot lines, kept-as-typed edits, accept one or many, throw away, keep; unique category names, swatch colours, chunked move-and-delete, seeding progress. `/api/ocr` reads BCA, GoPay and Krom through `src/lib/ocr.ts` (Anthropic SDK); `npm run ocr:try <folder>` for real screenshots.
- Redesign 1.3: pure logic in `src/lib` (`money`, `dates`, `periods`, `review`, `filters`, `swatches`) with unit tests: rupiah and bank forms, Monday-to-Sunday periods and like-for-like comparison, day series, category split, needs-a-look reasons (own transfer first), search, filters, four orders, `swatchFor()`. The old `dateRanges.ts` and `format.ts` stay until nothing imports them.
- Redesign 1.4: design tokens (`src/styles/tokens.css`) and Hanken Grotesk, new layout (safe areas, skip link, live region, toast), shared parts in `components/ui` (button, fields, chip, pill, sheet and dialog, back link, skeletons), bars, menu and offline notice in `components/app`, and `AppGate`, which puts setting up, loading, couldn't load or no connection in place of a screen. The old `Nav` is gone; old screens keep their old look until phase 2.
- Redesign 1.5: `e2e/app.spec.ts` covers the whole-app states against the test build: first open (Setting up, progress), loading, couldn't load and Try again, no connection at open and back online, losing the connection after load.
- Redesign R1: Phase 1 review (`redesign/reviews/R1-phase-1.md`). Fixed lost typing on a failed save (now `saveError`, not a load failure), review-reason order and required category ids, retry and nested-sheet focus, OCR size limit and dotted decimals, token-only colours; routed the rest to tasks 2.1–2.6.
- Redesign 2.1: the spend form (`components/spend-form`): one form to type in a spend, correct a waiting line (kept as typed) and change a saved one, with the category picker, the delete question and the "From the screenshot" crop. New `updateSpend` (checked, ends a suggestion); `formatRupiah(null)` says "No amount". Not mounted yet: the screens in 2.2 to 2.5 open it, and the old modals go with their pages.
- Redesign 2.2: home is the inbox (`components/inbox`): "N to check", Look right with a tick and the open row (crop, note, category chips), Need a look with one reason and two buttons (own-account transfers provisional, G5), and the bar that accepts exactly what looks right. Rows wait for their write and then leave; a failed save shows beside its line. Import tray, glance card, links and the empty states are 2.3.
- Fix in `useTransactions`: a written edit stays on top of the stored data until the write is acknowledged, so a line no longer jumps back to its old values (and out of its group) for a moment.
- Redesign 2.3: the rest of home. Import tray (screenshots read one at a time through `/api/ocr`, lines saved as each is read, Try again / Type in a spend / Dismiss), glance card, links, first use and All checked, "From N screenshots, added just now"; `/ocr` redirects to `/` and the old OCR page is gone. `e2e/home.spec.ts` (Claude replaced by `e2e/fixtures/ocr.ts`). Provisional: G6, rows that failed stay when more are added.
- Redesign 2.4: Spending (`/spending`, `components/spending`): total and like-for-like comparison, Week/Month with earlier and later, the day chart (step buttons for keyboard, sliding for pointers), where it went (top five, "Show N more", each opening All transactions with the period on), biggest spends opening the Change spend form. New `StepButton`, `Segmented`, `EmptyCard` in `components/ui`; the old donut, trend chart and palette are gone (`PeriodNav` goes with the old transactions page). `e2e/spending.spec.ts` runs with a fixed browser clock.
- Redesign 2.5: All transactions (`components/find`): search (store and note, marked), filters sheet (dates, categories, amount, source) with lemon chips and Clear all, four orders, 60 rows at a time, rows open the Change spend form (which deletes); Spending's category link arrives filtered. `e2e/transactions.spec.ts`. The old filters, period nav, spend modals, `dateRanges.ts` and `format.ts` are deleted.
- Redesign 2.6: Categories (`components/organise`): list with spend counts, one form to add or change (preview, name, 28 emoji or any typed, 13 colours, duplicate names refused), "Change order" with arrows and the quick-choices line, delete that checks first and moves spends and waiting lines. `useTransactionCounts` now returns `{ counts, loading, error, retry }`; a failure shows the couldn't-load state. Removes the old category modals and `Modal`. `e2e/categories.spec.ts` passes (8 tests).
- Redesign 2.7: `e2e/journey.spec.ts` uses the screens together: import and accept, find it on Spending, open its category's spends, change and delete it; a renamed category on every screen; losing the connection mid-use (writes refused with a reason, typed values kept, saves once back online).
- Redesign R2: Phase 2 review (`redesign/reviews/R2-phase-2.md`). Fixed offline writes from Throw away and the category picker, the form's values while accepting, Done waiting on the server, unretried failed edits, untrimmed accepts, the screenshot count, Spending forgetting its period, a crash on old bad dates, delete-question details; removed the unchecked writes; steadied flaky tests. Routed the rest to 3.2 and 3.4.
- Redesign 3.1: reverse check. Provisional G1 (unknown address, `src/app/not-found.tsx`) and G2 (unexpected error, `src/app/error.tsx`) in the app-failed shape (`NoticeScreen` in `components/app/boot-states.tsx`); title, description and home-screen name from the prototype (`layout.tsx`); five unused starter SVGs deleted. The manifest, icons and service worker stay for 3.2.
- Redesign 3.2: installable. Daybook manifest (standalone, maskable icon), prototype icons, `icon.svg` favicon, and a service worker that keeps the four screens, their scripts and the icons (never data or `/api/`) and replaces the old cache; `ServiceWorkerRegister` moved to `components/app`. `e2e/installable.spec.ts` (the only spec with the worker on): reload offline shows No connection.
- Redesign 3.3: share from iPhone. `POST /api/import` (Bearer `IMPORT_TOKEN`, constant-time; off without it) reads one shared image and writes waiting lines like an in-app import, tagged `importedVia: "share"`; plain-text answers for the Shortcut. Home's tray says "From your phone: read 2 screenshots" once per device (provisional G3). Guide: `docs/iphone-shortcut.md`.
- Redesign 3.4: accessibility pass. `npm run a11y` (`scripts/a11y.ts`, `--only <text>`) scans 29 screens and overlays at 390 and 1280 with axe on the test build, plus keyboard checks of the inbox, the form and the day chart; clean now. Fixed: the glance card and "Add category" button names now contain their visible words (WCAG 2.5.3); Spending is written in its phone order (total, where it went, day by day, biggest), so reading and tab order match what the phone shows. Server start-up for browser scripts moved to `scripts/test-servers.ts`.
